# Feedback Capture

## Workflow

1.  Identify explicit corrections, repeated preferences, and rejected
    approaches.
2.  Compare the correction with current knowledge and project
    conventions.
3.  Determine scope: one-off task, current project, or global
    preference.
4.  Identify the reason and evidence. Do not infer hidden intent.
5.  Draft the smallest update to a knowledge file, skill, or example.
6.  Check for conflicts with existing rules.
7.  Show the proposed change and ask for approval before persisting it.

## Promotion rules

-   One-off instruction: apply only to the current task.
-   Project constraint: record in project-level instructions.
-   Repeated cross-project preference: propose a global knowledge
    update.
-   Concrete code example: save as a reference example after removing
    secrets and private data.
-   Design reference: save only when the user explicitly selects it as a
    preferred reference.

Never claim the agent learns permanently from a chat. Durable learning
requires an approved file update or other explicit memory mechanism.
