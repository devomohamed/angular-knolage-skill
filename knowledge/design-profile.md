# Design Preference Profile

Status: PARTIALLY UNVERIFIED. Use existing project screens and
user-provided references as stronger evidence.

## Evidence priority

1.  Explicit user instruction for this task.
2.  Screenshot/reference explicitly selected by the user.
3.  Existing approved screens in the same product.
4.  Existing design tokens and shared components.
5.  This starter profile.
6.  Generic design conventions.

## Known requirements

-   Responsive layouts.
-   RTL and LTR support.
-   Dark and light theme support.
-   PrimeNG-based UI where the project uses PrimeNG.
-   Tailwind/SCSS according to existing project conventions.

## Must be calibrated

-   Brand palette and semantic colors.
-   Typography, font family, scale, weights, line heights.
-   Spacing scale and density.
-   Border radius, borders, shadows, elevation.
-   Sidebar width, header height, navigation behavior.
-   Card, table, form, modal, dropdown, and button appearance.
-   Icon family, icon size, placement, and stroke weight.
-   Mobile navigation and breakpoint behavior.
-   Empty, loading, error, success, disabled, and validation states.

## Visual implementation protocol

-   Extract a small token inventory from reference screenshots and
    current screens.
-   Distinguish global design language from page-specific layout.
-   Do not claim pixel-perfect matching without comparing rendered
    output.
-   Do not invent logos, brand colors, fonts, or assets.
-   When references conflict, ask which one is authoritative.
