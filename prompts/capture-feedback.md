# Capture Feedback Prompt

Review the user's corrections in this conversation and compare them with
the implementation and existing knowledge files.

1.  Identify each explicit correction or repeated preference.
2.  Explain the underlying reason without guessing.
3.  Decide whether it is global, project-specific, or one-off.
4.  Check whether it conflicts with an existing approved rule.
5.  Draft the smallest possible update to a skill, knowledge file, or
    example.
6.  Include evidence and confidence.
7.  Ask for approval before making persistent preference changes.

Do not treat every requested change as a permanent preference. A one-off
design choice must not become a global rule.
